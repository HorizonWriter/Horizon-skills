# Obsidian 规范条目脚手架（通用版）

基于 `wb-new-entry` 的骨架改造为**通用 Obsidian** 工具，并修正其两个致命缺陷：

1. 原 `wb-new-entry` 生成的关联板块链接是 `[[../角色/角色总览|角色一览]]` —— 带 `../`，会制造死链。
2. 原模板若表格内放链接不转义 `|`，会打散表格。

本 skill 生成的笔记**直接符合修复后的 vault 规范**：
- 链接用 **vault 根相对**（`[[角色/角色总览|角色一览]]`），不写 `../`
- 表格单元格内的 wikilink 别名分隔符 **转义为 `\|`**
- 段落/列表内的链接 **不转义** `|`

## 用法

```bash
python scripts/scaffold.py <vault_root> <板块/文件名.md> [--type 人物] [--name 全名] [--org 阵营] [--refs 目标|别名,目标2]
```

示例：

```bash
# 新建一个角色卡（人物模板）
python scripts/scaffold.py /path/to/vault 角色/林夕.md --type 人物 --name 林夕 --org 玄机城 --refs "组织/玄机城|玄机城"
```

## 生成的文件结构

```
# <显示名>

> （待补充）

## 基本档案

| 项目 | 内容 |
|------|------|
| 全名 | <名> |
| 阵营 | <org 或 —> |
| 状态 | 现存 |
| 核心标签 | — |

## 概述
（待补充）

**关联板块**：<根相对链接，段落内不转义>
```

## 为什么能减少试错

你 vault 之前 1338 个死链、43 个文件表格被打散，**根因就是旧工具生成了 `../` 和未转义的 `|`**。本 skill 从源头保证新笔记合规，配合 `obsidian-vault-doctor` 事后体检，形成「事前预防 + 事后修复」闭环。

## 安全

只**新建**文件，绝不修改已有文件，不调用任何会注入 `../` 的外部 register/fix-refs 脚本。

> 注：自动注册到索引页的功能**故意不做**（原 `entry-auto-register` 会注入 `../`）。需要同步索引请用 `obsidian-orphan-auditor` 找出缺条目后手动补，或用合规方式追加。
